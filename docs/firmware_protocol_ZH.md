# QnEvt 固件串口协议

本文档描述 QnEvt 兼容硬件熵节点与主机客户端之间的公开字节级协议。

它只公开传输格式和可观测 payload。固件内部实现、板卡设计文件、私有校准值、健康测试阈值和熵调理实现细节不属于当前公开范围。

## 传输层

默认二进制传输：

| 字段 | 值 |
| --- | --- |
| 物理链路 | UART 或 USB CDC 字节流 |
| UART 波特率 | `2000000` |
| UART TX | `GP0` |
| UART RX | `GP1` |
| 多字节顺序 | payload 中的多字节值默认大端，除非字段另有说明 |

主机应将输入流视为连续的帧序列。

## 帧格式

```text
+--------+------+--------+---------+----------+
| Sync   | Type | Length | Payload | CRC16    |
| 1 byte | 1 B  | 1 B    | 0-255 B | 2 bytes  |
+--------+------+--------+---------+----------+
```

| 字段 | 说明 |
| --- | --- |
| `Sync` | 固定为 `0xAA`。主机可以通过扫描这个字节重新同步。 |
| `Type` | 包类型，见下方类型表。 |
| `Length` | payload 字节长度。 |
| `Payload` | 按包类型定义的载荷。 |
| `CRC16` | 对 `Type || Length || Payload` 计算 CRC16-CCITT，初始值 `0xFFFF`，多项式 `0x1021`，存储时低字节在前、高字节在后。 |

最小帧长度为 5 字节，最大帧长度为 260 字节。

## 包类型

| Type | 名称 | 方向 | Payload 长度 | 说明 |
| --- | --- | --- | ---: | --- |
| `0x01` | `RANDOM` | 节点到主机 | `48` | 主熵输出包。 |
| `0x02` | `WARN` | 节点到主机 | `1` | 非致命健康告警。 |
| `0x03` | `TELEMETRY` | 节点到主机 | `10` | 简短健康遥测快照。 |
| `0xE0` | `ERROR` | 节点到主机 | `1` | 硬件或健康测试错误，通常意味着输出应停止。 |
| `0x88` | `CONTROL` | 主机到节点 | `0` 或 `1` | 可选控制命令。 |

## `RANDOM` Payload

`RANDOM` 包包含 48 字节：

| 偏移 | 长度 | 说明 |
| ---: | ---: | --- |
| `0` | `16` | 8 个原始 16-bit 传感器采样值，大端。用于监控和桥接端诊断。 |
| `16` | `32` | 调理后的熵块。主机客户端应使用这个字段作为随机字节材料。 |

当节点处于错误状态时，主机应忽略 `RANDOM` 包；收到 `ERROR` 包后，应停止接受该节点输出，直到设备重置或按实现策略确认恢复。

## `TELEMETRY` Payload

`TELEMETRY` 包包含 10 字节：

| 偏移 | 长度 | 说明 |
| ---: | ---: | --- |
| `0` | `2` | 熵估计指标乘以 1000 后的无符号整数，大端。 |
| `2` | `1` | bit 0 高电平比例百分比。 |
| `3` | `1` | bit 1 高电平比例百分比。 |
| `4` | `1` | bit 2 高电平比例百分比。 |
| `5` | `1` | bit 3 高电平比例百分比。 |
| `6` | `1` | bit 4 高电平比例百分比。 |
| `7` | `1` | 重复计数失败计数器低字节。 |
| `8` | `1` | 自适应比例失败计数器低字节。 |
| `9` | `1` | 节点健康状态：`0` 正常，`1` 告警，`2` 失败。 |

主机可以展示这些信息、写入本地诊断，或作为上传熵批次旁边的元数据提交。

## 告警码

| 代码 | 含义 |
| --- | --- |
| `0x01` | 熵估计偏低告警。 |
| `0x02` | bit 偏置告警。 |

告警是非致命状态。主机可以继续读取 `RANDOM` 包，但应将对应批次标记为健康状态降级。

## 错误码

| 代码 | 含义 |
| --- | --- |
| `0x01` | 健康测试失败。 |
| `0x05` | VL53L1X I2C 通信失败。 |
| `0x06` | VL53L1X 读取超时。 |
| `0x07` | 传感器饱和或无效距离状态。 |
| `0x08` | 传感器输出疑似卡死。 |

错误表示当前熵输出不可用。主机客户端应停止接受该节点的随机字节，直到确认恢复。

## 控制命令

`CONTROL` 包由主机发往节点：

| Payload | 含义 |
| --- | --- |
| 空 payload 或 `00` | 重启固件。 |
| `01` | 进入 USB BOOTSEL 模式。 |

主机到节点的控制包也使用同样的帧结构和 CRC 规则。

## 主机解析要求

兼容主机解析器应该：

1. 扫描 `0xAA`。
2. 读取 `Type`、`Length`、`Payload` 和两个 CRC 字节。
3. 对 `Type || Length || Payload` 重新计算 CRC16-CCITT。
4. 丢弃 CRC 错误或长度不支持的帧。
5. 将 `ERROR` 视为输出停止状态。
6. 只使用 `RANDOM` 中 32 字节调理后部分作为随机字节材料。
7. 将 telemetry 作为元数据保存或上传，不把它当作 secret。

## 隐私边界

这个协议不要求公开固件源码、校准文件、板卡设计文件、设备序列号、凭证、生产服务端 URL 或部署配置。公开主机集成应依赖这个协议契约，而不是依赖私有固件内部实现。
